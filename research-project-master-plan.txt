ADAPTIVE SPECTRAL CAMOUFLAGE FOR MIXED-SIGNAL SIDE CHANNELS
MASTER PLAN: READ THIS FIRST AFTER A LONG BREAK

0. PURPOSE
==========

Research question:

Can a resource-constrained BLE/IoT device commit to a randomized combination of
clock/frequency selection and dummy-current/noise shaping that reduces physical
power/EM information leakage against an adaptive observer, while satisfying
energy, latency, and reliability constraints?

This is a defensive research project. It is not a guide to compromise consumer
devices. Use synthetic secrets and only owned or authorized boards.

The intended deliverable is a reproducible research artifact and, if the
evidence is strong, an advisor-reviewed paper. A GitHub repository by itself is
not the research result. The result is the combination of a falsifiable model,
mathematics, baselines, experiments, and honest limitations.


1. WHAT TO REFRESH
==================

Do not wait to finish entire textbooks. Refresh each item immediately before it
is used.

Probability (EECS 126 level)
- Conditional probability and Bayes' rule.
- Random variables, expectation, covariance, Gaussian models.
- Maximum likelihood and MAP estimation.
- Markov chains only if the dynamic extension is reached.
- Hypothesis testing, type-I/type-II errors, ROC curves.
- Entropy H(X), conditional entropy H(X|Y), mutual information I(X;Y).

Optimization (EECS 127 / Boyd level)
- Convex sets/functions and Jensen's inequality.
- Lagrangians, KKT conditions, primal/dual interpretation.
- Linear programming and minimax matrix games.
- Robust optimization with bounded or distributional uncertainty.
- cvxpy formulation and post-solve residual checks.

Signals and systems (EECS 16A/16B and RF review)
- Fourier transform, PSD, convolution, transfer functions.
- Sampling, aliasing, windows, leakage, Welch PSD.
- Bode magnitude/phase and poles/zeros.
- SNR and filtering; why an observer can remove naive broadband noise.
- PDN impedance Z_PDN(f), switching current, conducted versus radiated coupling.

Hardware security
- Leakage model: Y = h(S, X, A_D, A_A) + N.
- Difference-of-means and Welch t-test/TVLA.
- Correlation and template attacks as evaluation tools on synthetic test data.
- Guessing entropy and success probability.
- Countermeasure classes: masking, hiding, shuffling, random timing, noise.

Game theory
- Zero-sum normal-form games and mixed strategies.
- Minimax theorem and LP solution.
- Bayesian games: private observer type theta with prior p(theta).
- Stackelberg commitment: leader commits; follower best-responds.
- Why a game is warranted only when the observer adapts strategically.


2. CORE PHYSICAL MODEL
======================

Let:

S       synthetic secret or sensitive intermediate
X       public input/plaintext
d       defender action
a       observer action
theta   observer type
Y       measured trace or feature vector

First channel:

Y = alpha(a) L(S, X) + B_d + N_d + W

where L is secret-dependent switching leakage, B_d is defense-induced structured
activity, N_d is stochastic injected activity, and W is ambient/capture noise.
The observer action controls a bandpass/filter/probe gain alpha and trace budget.

Initial defender actions:
D0 no defense
D1 fixed dummy load
D2 random frequency mode
D3 shaped stochastic policy over frequency and dummy-load levels

Initial observer actions:
A0 low-frequency conducted-power feature
A1 clock-fundamental EM band
A2 harmonic band
A3 adaptive/high-pass preprocessing

Costs:

J_D = leakage + lambda_E * normalized_energy
              + lambda_L * normalized_latency
              + lambda_F * false_alarm_rate

U_A = leakage_or_success - c_trace * traces - c_band * bandwidth

Never combine quantities with incompatible units without normalization. Record
the reference energy, latency, and trace budget used to make each dimensionless.


3. TWELVE STAGES AND EXIT GATES
==============================

Stage 0: environment and notebook discipline (1–2 sessions)
- Create Python environment and run tests.
- Create an experiment ID convention:
  YYYYMMDD_model_defense_observer_seed
- Every run writes JSON configuration/results; figures are regenerated, never
  manually edited.
EXIT: clean setup on a second machine from requirements and README.

Stage 1: signals refresher and synthetic leakage (3–5 sessions)
- Generate traces with known secret-dependent mean shift.
- Plot time waveform, PSD, spectrogram, and filter responses.
- Compute Welch t statistic and a discrete/binning MI estimate.
- Verify leakage rises with alpha and falls with Gaussian noise.
EXIT: unit tests pass and trends match analytic expectations.

Stage 2: fixed baselines (3–5 sessions)
- Implement no defense, fixed Gaussian/dummy noise, and random-frequency modes.
- Add an adaptive observer that selects the best band after calibration.
- Show the expected failure case: a fixed defense looks good against a fixed
  observer but loses advantage after band selection/filtering.
EXIT: confidence intervals from at least 30 independent seeds.

Stage 2D: digital-circuit trace factory and large-data track (parallel, 2-4 weeks)
Detailed design: theory/high-volume-data-and-digital-circuit-extension.md
This stage runs alongside Stages 2-6 and supplies the data volume those stages
need. It does not replace any existing stage or relax any guardrail.
- Write a synthetic switching kernel and a small AES core in Verilog/
  SystemVerilog, wrapped by clock gating, a frequency-hopping/DVFS controller,
  a dummy switching bank, and an LFSR or CSPRNG randomness source.
- Simulate with iverilog (reference) and Verilator (scale). Extract per-cycle
  switching activity from VCD; use SAIF only for aggregate power cross-checks.
- Push activity through the Section 2 channel model to produce traces.
- Optional later: Yosys synthesis to Sky130 standard cells, then gate-level
  simulation with SDF timing so glitch activity is included; OpenLane only if
  interconnect parasitics turn out to matter.
- Trace-count progression, each phase gated by the previous one:
    P0  1k      pipeline smoke test against known ground truth
    P1  >=10k   first real statistics; estimate ICC and design effect
    P2  50k     first payoff matrix with per-cell confidence intervals
    P3  100k-1M hierarchical model, MI convergence, equilibrium uncertainty
    P4  10k-50k gate-level with timing, to test the behavioral ordering
  Do not jump to 100k before the 10k analysis is clean. Scale multiplies both
  real effects and systematic generator bugs.
- Storage: chunked Zarr for the N x T trace array, Parquet for the per-trace
  feature/label/metadata table, JSON manifest with checksums. Declare the
  schema before generating. Never mutate a published dataset; publish a new
  version.
- Seeds: one master seed with separate derived streams for simulation, noise,
  defense randomness, plaintexts, and keys.
- Splits: group by key, session, netlist, and PVT corner. Never split traces at
  random. Assert split disjointness in code.
- Analysis: TVLA with permutation max-statistic thresholds, session-level
  cluster bootstrap, mutual information with Miller-Madow plus shuffle-null
  plus 1/N extrapolation, GLM/logistic baseline, and a Bayesian hierarchical
  model across sessions/netlists/corners. Machine learning only as an attack
  baseline, compared against CPA and the GLM on identical grouped splits.
- Prefer more sessions over more traces per session. Effective sample size
  saturates near G/ICC regardless of traces per session.
- Synthesis timing/power/area reports supply the lambda_E and lambda_L
  overheads in Section 2, replacing assumed constants.
EXIT: reproducible >=10k dataset with manifest and checksums; null calibration
returns no detection on zero-leakage data; ground-truth DUT recovers its known
leakage; effect intervals are computed at session level with G >= 30; the
behavioral-versus-gate-level comparison has a pre-declared equivalence margin.

Switching activity from simulation is a proxy for current demand. It is not
silicon EM leakage and must never be reported as a measurement. Calibration
against owned hardware happens only at Stage 8 / digital-track phase R4, and the proxy caveat belongs
in the abstract, not only the limitations section.

Stage 3: finite zero-sum game (1 week)
- Estimate payoff matrix M[d,a] using held-out Monte Carlo runs.
- Solve defender min_p max_a p^T M[:,a] using scipy.optimize.linprog.
- Solve the dual observer problem and check primal-dual gap.
- Enumerate pure strategies to show whether mixing matters.
EXIT: solver result, dual verification, and hand-checkable 2x2 example agree.

Stage 4: Bayesian observer types (1–2 weeks)
- Types: passive band-limited, filtering/template, resource-rich.
- Define prior p(theta) from scenarios, not invented precision.
- Solve a leader commitment with a best response for each type.
- Stress prior misspecification over a simplex/grid.
EXIT: policy remains useful over a stated uncertainty region or fails honestly.

Stage 5: mathematical results (parallel, 2–6 weeks)
Candidate A: equilibrium existence for compact/finite action spaces.
Candidate B: LP equivalence for finite zero-sum special case.
Candidate C: leakage-success bound using Fano for M-ary secrets.
Candidate D: robust policy under an uncertainty set for observer-type prior.
Candidate E: sample-complexity/confidence bound for estimated payoff matrix.
EXIT: every theorem has assumptions, statement, proof, and numerical assumption
check; otherwise label it proof sketch or conjecture.

Stage 6: trace replay (1–2 weeks)
- Use a legal public trace dataset or captures from synthetic firmware.
- Freeze train/calibration/test split by capture session, not random trace, to
  avoid leakage between near-identical acquisitions.
- Compare fixed and adaptive observers.
EXIT: raw data checksum, preprocessing script, and repeatable table/figure.

Stage 7: bench decision (one review meeting)
Proceed only if:
- effect size exceeds expected instrument noise;
- policy uses controls available on a chosen board;
- a capture setup is affordable/available;
- simulation has a clear falsifiable prediction.
Otherwise publish the theory/simulation honestly or revise the model.

Stage 8: safe bench prototype (2–4 weeks)
Recommended target: owned STM32/nRF52/ESP32-class board executing synthetic AES
or a synthetic leakage kernel. Use a shunt/scope for conducted power first.
Near-field EM is optional and follows only after conducted capture works.
- GPIO trigger around synthetic operation.
- Known random keys/plaintexts generated by test harness.
- Firmware modes implement defense actions.
- Measure actual energy and latency, not estimated instruction counts.
EXIT: stable trigger, repeatable baseline leakage, no unexplained clipping.

Stage 9: adaptive bench experiment (2–4 weeks)
- Calibrate observer actions on separate traces.
- Commit defender policy before held-out evaluation.
- Randomize run order to avoid temperature/time confounds.
- Log supply, clock mode, probe location, gain, sample rate, bandwidth.
EXIT: preregistered primary metric and confidence interval; all exclusions logged.

Stage 10: ablation and robustness (1–2 weeks)
- Remove frequency mixing, dummy activity, and robust term one at a time.
- Sweep energy and latency prices.
- Test unseen observer filter and shifted channel gain.
- Compare against robust convex optimization without strategic follower.
EXIT: identify exactly which component creates any advantage.

Stage 11: paper and artifact freeze (2 weeks)
- Freeze commit, environment, data manifest, and figure-generation command.
- Fill claims-to-evidence table.
- Ask an advisor to challenge novelty, assumptions, and statistical design.
- Release only data/firmware that is safe and legally redistributable.
EXIT: another person can regenerate main results from the artifact.


4. BUILD VERSUS BUY
===================

Buy or borrow:
- oscilloscope/capture ADC with adequate bandwidth and memory;
- near-field H probe and low-noise amplifier if EM stage is justified;
- regulated bench supply, shunt, cables, attenuators, shield box materials;
- ChipWhisperer Lite only if its capture/glitch features are actually needed.

Build:
- small switchable dummy-load daughterboard only if existing board loads cannot
  expose controllable load levels;
- test firmware, trigger interface, and safe fixture;
- optional PCB after breadboard/fixture parasitics are characterized.

Do not build:
- commodity buck converter, charger, SDR, scope, or VNA;
- high-voltage/high-energy fault injector;
- custom IC before the model is validated.

Custom PCB gate:
Design in KiCad only if repeatable probe placement, current sensing, or load
switching cannot be achieved with a safe fixture. If gated in, simulate the
load switch and PDN in LTspice; include Bode/impedance plots and test points.

6. STATISTICS AND REPORTING
===========================

- Separate exploratory and confirmatory experiments.
- State primary metric before final run.
- Report effect estimate and 95% interval, not only p-values.
- Use session-level bootstrap when traces within a session are correlated.
- Correct for multiple comparisons when searching many time samples/bands.
- TVLA |t| > 4.5 is an engineering screening convention, not proof of security.
- A failed attack is not evidence of no leakage.
- MI estimators are biased; include estimator choice and synthetic calibration.
- Include seeds and negative results.

Additional rules once trace counts reach 10k and above (see
theory/high-volume-data-and-digital-circuit-extension.md for formulas):

- Report the number of independent sessions G next to the number of traces N.
  A large N over a small G is a small experiment wearing a costume.
- Plan sample size in advance, including the design effect
  DEFF = 1 + (traces_per_session - 1) * ICC. A tiny ICC can still inflate the
  required N by an order of magnitude.
- Because generation is incremental, fix the stopping rule before generating:
  either fixed-n (the default for confirmatory runs), a group-sequential design
  with an alpha-spending function, or an anytime-valid confidence sequence or
  e-value. Never run until significant and then stop.
- Touch the test split once per declared hypothesis. Log every additional look
  and count it in the family size.
- At large N, p-values are uninformative and effect sizes are everything.
  TVLA |t| is not comparable across phases because it grows with sqrt(N);
  report Cohen's d with an interval alongside it.
- Propagate payoff-matrix uncertainty into the equilibrium rather than solving
  once at the point estimate. Report an interval for the equilibrium value and
  a support-stability frequency for each action in the mixed strategy; the
  value is Lipschitz in the matrix but the policy is not.


7. STOP/PIVOT RULES
===================

Pivot from “game” to robust optimization if the observer best response never
changes the optimal policy or if strategic adaptation adds no explanatory power.

Pivot from key-recovery framing to generic classification/privacy leakage if
available safe traces cannot support cryptographic evaluation.

Stop hardware purchases if synthetic and trace-replay studies do not predict an
effect larger than capture uncertainty.

Do not submit if the central proof remains a conjecture, baselines are weak, or
the novelty search reveals the same model and experiment.
